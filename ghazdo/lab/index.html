GitHub Advanced Security for Azure DevOps Lab Guide

Duration: 10 minutes, included in the 90-minute workshop
Format: Four no-login paper or local-notes exercises
Audience: Azure DevOps administrators, developers, security engineers, and engineering leads
Repository: None required; no repository changes or scans
Status: Authoring draft; learning and facilitation review pending

Lab Overview

Practice pricing, setup readiness, secret response, and CodeQL decisions. The workshop guide supplies the instruction. Every scenario is fictional and independent; no answer depends on earlier work.

These exercises do not activate products, approve costs, or authorize changes. Optional existing-repository setup belongs in the separate setup guide, before or after the presentation.

Prerequisites

  • Basic familiarity with Git, pull requests, and Azure DevOps projects.
  • Paper or a local note-taking tool and access to the shared screen.
  • No account, license, installation, credential, repository clone, or pipeline run.

Setup

  1. Open this guide or follow the shared screen.
  2. Prepare paper or a local note.
  3. Write four headings: Pricing, Setup, Secrets, CodeQL.

Setup checkpoint: You can respond without logging in or opening a cloud resource. The facilitator can read all scenarios aloud if links are unavailable.

1. Estimate the monthly cost (3 min)

Objective: Estimate monthly product costs using active committers (objective 2).
Starting state: The same 20 developers use both products and meet the last-90-days push rule.

Input

20 active committers will use both products.
Secret Protection: $19 per active committer/month.
Code Security: $30 per active committer/month.
What is the monthly product estimate at USD list prices?
What does it exclude?

Steps

  1. Calculate Secret Protection for 20 developers.
  2. Calculate Code Security for the same 20 developers.
  3. Add the subtotals and name one excluded cost. Use two minutes for steps 1–3.
  4. Use the final minute to compare answers.

Expected Result / Answer

Product Calculation Monthly cost
Secret Protection 20 × $19 $380
Code Security 20 × $30 $600
Total $380 + $600 $980

Pipeline usage and AI features are separate. This is a list-price estimate, not a quote. The presentation's same-25-developer example is $1,225/month.

An active committer has commits present in a push made in the last 90 days, even if the original commit is older. Count separately per product, deduplicating each developer within the same Azure subscription, including multiple protected repositories or linked organizations.

Success Criteria

  • ✅ Secret Protection subtotal is $380/month.
  • ✅ Code Security subtotal is $600/month and total is $980/month.
  • ✅ Identify pipeline usage or AI features as an excluded cost.

Cleanup: None; retain or discard notes.

2. Before you enable security (2 min)

Objective: Identify approval, permissions, and pipeline prerequisites (objective 3).
Starting state: A fictional team has chosen an existing Azure DevOps Services project and Azure Repos Git repository.

Input

The team wants to enable Advanced Security.
The cost has not been approved.
You can view alerts, but cannot change security settings.
The pipeline agent has not been checked.
What should you confirm before proceeding?

Steps

  1. In 30 seconds, decide whether the team is ready.
  2. In 30 seconds, identify the three missing checks.
  3. In the final minute, compare answers and name the appropriate owners.

Expected Result / Answer

Not yet. Complete these checks before activation:

Check Who to involve
Approval for product and pipeline costs Budget and product owners
Advanced Security: Manage settings Authorized settings owner
Agent capacity and permission to run supported scanning tasks Pipeline owner

Read alerts permits investigation; Manage and dismiss alerts permits authorized response. Neither replaces settings permission. Repository and pipeline rights are separate. Check language/build compatibility, feeds, and effective access before running.

Success Criteria

  • ✅ Explain why activation should wait.
  • ✅ Name all three missing checks.
  • ✅ Name Advanced Security: Manage settings without recommending broad administrator access.

Cleanup: None; do not change resources or permissions.

3. Respond to an exposed secret (2 min)

Objective: Distinguish exposure response from push prevention (objective 4).
Starting state: A fictional alert concerns a real credential already pushed. No credential value is supplied or needed.

Input

A. Remove the exposed value using your approved cleanup process.
B. Close the alert after confirming the issue is resolved.
C. Revoke or replace the credential.
D. Confirm the credential no longer works and cleanup is complete.

Steps

  1. In 45 seconds, put the four actions in order.
  2. In 15 seconds, explain why deleting the value from the current file is insufficient.
  3. Use the final minute to compare answers and contrast exposure with a blocked push.

Expected Result / Answer

C -> A -> D -> B. Coordinate with the credential owner: revoke or replace, remove the exposed value, confirm resolution, then close the alert. Deletion or alert closure does not revoke the credential.

Repository secret scanning discovers historical exposure. Push protection blocks supported secrets in new pushes; it does not undo an earlier leak. For an unpushed secret, coordinate approved removal from all affected outgoing commits, not just the latest file.

Success Criteria

  • ✅ Order all four actions correctly.
  • ✅ Explain why credential replacement is needed after exposure.
  • ✅ Distinguish historical detection from prevention of a new push.

Cleanup: None; do not create credentials, fake secrets, or repository fixtures.

4. Choose your CodeQL setup (3 min)

Objective: Choose setup and describe fix verification (objective 6).
Starting state: A fictional team has a proposed code fix but has not confirmed remediation.

Input

The team needs scans on the default and release branches.
The application needs a custom build.
Would you choose default or advanced setup?
How would you confirm that a code fix resolved the alert?

Steps

  1. In one minute, choose setup and explain the branch/build reason.
  2. In one minute, describe how to confirm the fix.
  3. Use the final minute to compare answers.

Expected Result / Answer

  • Advanced setup fits additional branches and a custom build. Default setup scans the default branch on a schedule for supported languages.
  • Review the code change, run relevant tests, and complete a CodeQL rescan on the same branch with comparable configuration. Review the result to confirm resolution.
  • A proposed pull request, product activation, or prepared YAML alone does not confirm the fix.

Success Criteria

  • ✅ Choose advanced setup for additional branches/custom build.
  • ✅ Require code review and relevant tests.
  • ✅ Require a completed same-branch rescan and result review.

Cleanup: None; do not queue a scan or change a repository.

Troubleshooting and Backup

  • No network: the facilitator reads the scenarios and answers aloud.
  • No note-taking tool: use paper or verbal responses.
  • Pricing difficulty: calculate each product's subtotal separately, then add.
  • Uncertain real-world permissions or support: record a follow-up question; these fictional scenarios are not approvals.

Overall Cleanup

Only notes were created. No accounts, credentials, repositories, branches, settings, pipelines, or processes should have changed.
